## 安装

各平台的安装步骤、系统拦截怎么放行、搜不到设备时该查什么，
见仓库里的 [安装说明](https://github.com/cat-clever/ADisplay/blob/main/docs/安装说明.md)。

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows x64 | `adisplay-windows-x64.zip` | 解压后运行 `ADisplay.exe`。首次运行放行 SmartScreen 与**防火墙**（必须勾「专用网络」，否则手机搜不到设备）。 |
| Windows ARM64 | `adisplay-windows-arm64.zip` | 同上。适用于骁龙 X 系列等 ARM 笔记本，原生运行。 |
| macOS（Apple Silicon + Intel） | `adisplay-macos-universal.dmg` | 打开 dmg 拖进「应用程序」。首次启动需在「隐私与安全性」放行，并**允许「本地网络」权限**（否则广播会被系统静默拦掉）。 |
| Android TV / 电视盒子 | `adisplay-android-tv.apk` | U 盘或 `adb install` 侧载。 |

### 这一版的修复

- **iPhone 的「屏幕镜像」不再只看得到、点不动了。** 之前 `protocols/airplay/` 是个空
  目录 —— mDNS 把 `_airplay._tcp` 广播出去了，7000 端口上却没有任何东西应答，手机点
  下去自然毫无反应。现在接上了 UxPlay 的协议层（只取它的 `lib/`，不带 GStreamer 渲染
  器），由它提供 `/info`、配对、FairPlay 握手与镜像流的收流解密。

- **mDNS 通告里补上了缺失的设备公钥。** `_airplay._tcp` 与 `_raop._tcp` 的 TXT 记录
  里一直没有 `pk`，而 iOS 的配对校验要靠它核对接收端身份；`features` 的取值也与上游
  真机验证过的那一组不同。两处都对齐了，而且广播内容与协议层的 `/info` 应答现在从
  同一份定义取，设备 id 直接调用协议层自己的格式化函数 —— 这两份内容只要差一个字，
  iOS 就会把同一台电脑当成两台设备，表现又是「看得见、连不上」。

- **中转拉远端播放列表改用自建的 HTTP 读取，并把判断依据写进日志。** 手机上的投屏
  代理是「边拉上游边转发」的，正文分很多次、中间带停顿地送过来。原来的实现（httplib
  客户端）在读取超时或提前 EOF 时一律报「读失败」，而且会把已经收到的正文丢掉 ——
  手里只剩一句话，既不知道收了多少字节，也不知道是对端提前关了还是我们等得不耐烦。
  中转这条路径改了三轮请求头都没找对方向，就是卡在这里。现在：读超时按「多久没有
  新字节」算，慢速但活着的传输不会被误杀；正文短于声明长度时用 `Range` 续传补齐；
  无论成败，声明多少、实收多少、续传几次、是否超时都会记进日志。

- **上游只支持 MinGW 构建 Windows，而我们是 MSVC。** 缺口清点下来只有 `usleep`、
  `clock_gettime`、`SOL_TCP` 和 pthread 一组，各自补了一层薄垫片即可 —— 不值得为此
  换编译器。其中 pthread 是自己写的 Win32 包装（十三个接口），顺带去掉了一个依赖。

### 这一版能做什么

- **手机投屏列表里能看到这台电脑**（mDNS 与 SSDP 广播）。
- **Android 视频 App 推过来的视频真的能播出画面与声音**，播放、暂停、拖动进度、调音量都由手机控制。
  解码、硬件加速与音画同步交给各平台自带的播放器（macOS 用 AVPlayer、Windows 用
  Media Foundation、电视端用 ExoPlayer），所以常见封装与编码都能放。
- **H.265 装在 MPEG-TS 里的片源也能放。** 这类片源（国内不少投屏 App 是直通源编码的）
  系统播放器常常不认，接收端会在本地把封装换成 fMP4 再交给播放器 —— 视频不重编码，
  所以不吃 CPU、画质不损失。
- **iPhone 能连上本机了**，并且能通过 AirPlay 推送视频（手机把一条 HLS 地址发过来，
  由接收端自己拉流播放）。这条路径和 Android 那边完全一样，所以上面那些能力它同样有。
- **电视端可用了**：能看日志、能接收投屏、能用遥控器操作。
- 设备名称可以随时修改，即刻生效，不需要重启软件或重新配对。

### 这一版还不能做什么

- **AirPlay 镜像还没有画面。** iPhone 的「屏幕镜像」现在能连上，镜像流的帧也已经
  收到并解密（日志里会打出首帧大小与画面尺寸，之后每 5 秒一行帧计数），但那些帧
  还没有送进解码器 —— 渲染那一步是下一步要做的。想确认连上了没有，看日志里有没有
  「AirPlay 屏幕镜像已开始」和随后的帧计数。
- **AirPlay 的连接确认弹窗还没有。** 手机请求连接时一律放行（与 Android 那边一致），
  也就是说任何设备都能连，没有二次确认。这是批次 6 的内容。
- **只有 64 位电视盒子能用。** 这一版只出了 arm64-v8a 的库，32 位老盒子装不上。
  电视端也还没编 AirPlay 协议层，Android 目前只能用 DLNA 那条路径。
- **连接确认弹窗、白名单、托盘常驻、开机自启、中英双语还没有**（批次 6）。
- **Linux 桌面端还没有界面。** 核心库在 Linux 上能编、测试也过，但没有 GTK 界面，
  所以 Linux 暂时只能当开发用途。
- 电视端的「停止接收投屏」会停掉整个接收服务，需要重新开启一次。
